# NHIS 설계 항목과 변수·신청 근거 연결

현재 프로젝트 지침, 승인 연구계획·SAP와 사용자 결정이 우선한다. 이 참조는 보유 자료를 읽는 방법이며 특정 연구의 변수·코드·임상 정의를 제공하지 않는다. 실제 SAS 자료가 오기 전에도 문서 근거가 확인된 후보 표를 작성할 수 있다.

공통 참고자료 정리는 현재 연구나 신청이 진행 중임을 뜻하지 않는다. 신청양식은 테이블·변수명·설명과 향후 신청 항목을 확인하는 참고자료로 사용한다. 이 경우 신청 여부는 **해당 없음—참고용**으로 적고, 현재 신청서나 승인 근거가 없다는 이유로 작업을 보류하거나 미완료로 표시하지 않는다. 실제 신청 업무를 요청받았을 때만 해당 연구의 선택·요청연도·제출/승인 상태를 대조한다.

## 한 표로 연결한다

공통 자료정리는 기존 자료 안내에, 특정 연구 설계는 기존 SAP·변수목록에 아래 여섯 열을 사용한다. 별도 파일이나 문서 묶음을 의무적으로 만들지 않는다. 기본 한 행은 연구 항목×테이블×변수×동일 명세의 연도범위다. 같은 개념이라도 연도별 이름·값·단위가 다르면 행을 나눈다.

| 연구에 필요한 항목 | 테이블·변수명 | 설명·값 코드 | 적용 연도 | 신청 여부 | 출처 시트·셀 |
|---|---|---|---|---|---|
| 항목 ID, 연구상 필요성과 역할 | NHIS 자료/단계, 테이블, 원문 변수명. 실행 라이브러리명 추정 금지 | 뜻, 값→뜻, 단위·형식·결측 코드 중 원문에서 확인한 것 | 명세의 연도범위 / 연구 필요연도 구분. 신청연도는 실제 신청 시만 기록 | 자료정리는 해당 없음—참고용. 실제 신청 업무에서만 선택·제출·승인 상태 구분 | 파일·판본, 시트, 변수/설명/값/연도 근거 셀. 양식의 선택칸은 참고 위치이며 실제 상태 근거와 구분 |

변수·값·적용연도 출처가 없으면 ‘미확인’과 필요한 근거를 적는다. 비어 있는 참고 양식은 현재 신청 상태의 근거가 아니다. 실제 신청 현황을 검토하는 업무에 한해 해당 연구 신청서의 선택칸·연도·현재 판본으로 상태를 판단한다. 문서에 있는 변수와 실제 제공된 변수도 구분한다.

## 질문에 맞는 자료부터 읽는다

현재 프로젝트가 지정한 통합 변수목록이 있으면 먼저 검색한다. 관리 라이브러리의 `nhis-variable-catalog-20261111`은 변수 CSV/Excel, 값코드 목록, 출처 해시·시트별 범위를 연결한다. 테이블·변수명·연도·자료 ID로 필요한 행만 고르고 출처 시트·셀을 다시 확인한다. 값 코드의 조건·맥락과 원문 병합 설명도 함께 읽는다. 같은 이름의 다른 판본을 하나로 합치거나 명세 행 수를 고유 변수 개수로 해석하지 않는다.

통합 목록은 전체 변수의 참고 사전이므로 `연구에 필요한 항목`은 비어 있고 신청 여부는 해당 없음이다. 실제 연구에서는 필요한 항목을 골라 해당 연구의 변수표를 작성한다. 원문에 테이블·연도·개별 변수명이 없는 부분은 미기재/전체변수 표기를 유지한다. 원본 해시가 달라졌거나 목록 범위 밖이면 해당 원문을 새로 확인한다. 목록이 없는 portable 환경에서도 아래 자료별 확인 절차로 진행할 수 있으며, 로컬 통합 목록이 번들에 포함되어 있다고 가정하지 않는다.

| 확인할 질문 | 먼저 읽을 자료 | 표에 옮기기 전 확인 |
|---|---|---|
| 어떤 정보가 연구에 필요한가? | 현재 연구계획·SAP·사용자 결정 | 노출·결과·공변량·선정/제외·대상자 연결·기준시점/추적과 필요한 기간. 사례 연구의 기준 자동 채택 금지 |
| 해당 항목은 어느 테이블·변수인가? | 프로젝트의 NHIS_code_book/통합 코드북과 기본 제공 컬럼 레이아웃 | 변수명·설명·값 코드의 정확한 셀, 판본 차이, 테이블/연결키. 표준 변수 전체가 해당 연구에 제공된다고 가정하지 않음 |
| 연구 연도에 같은 뜻으로 존재하나? | 해당 연도의 일반검진·문진·기관·특화검진 상세 레이아웃 | 연도별 이름·코드·단위·형식. ‘전체변수’는 상세 목록이 아니며 서식 작성연도는 자료 적용연도가 아님 |
| 양식에는 어떤 항목이 안내되어 있나? | 참고용 customized_DB_application | 테이블·변수명·설명, 기본/추가 구성과 향후 신청 위치. 실제 신청 업무일 때만 해당 연구의 선택칸·요청연도·추출 범위·제출/승인을 대조 |
| 질환·약제·행위를 어떤 코드로 정의하나? | 적합한 판본의 KCD/약제/수가 자료와 연구별 근거 | 원문 코드, 포함/제외 하위범위, 코드체계·유효기간. 코드 사전만으로 진단 횟수·관찰창·결합조건을 결정하지 않음 |
| 이제 코드에서 사용할 수 있나? | 실제 제공 inventory·생성 코드와 승인 요청 계약 | 실제 필드 존재·자료형·길이·키·기간. 문서 후보를 실행 매핑으로 확정하기 전에 확인 |

현재 프로젝트의 지정 자료 목록을 먼저 사용한다. 관리 라이브러리에 접근할 수 있으면 그 README의 `nhis-design-map-20261111`에서 실제 파일·시트·셀을 찾는다. 접근할 수 없으면 사용자가 제공한 자료로 같은 표를 작성한다. 이 번들에는 원본 코드북·신청서가 들어 있지 않으므로 내용을 읽었다고 주장하거나 셀 주소를 만들어 쓰지 않는다. 전체 Drive 검색은 하지 않는다.

## 셀과 연도를 기록하는 규칙

- 변수명/설명과 값 코드가 다른 시트에 있으면 각각의 출처를 쓴다. ‘코드북 참조’만으로 끝내지 않는다. 파일 판본이나 내용을 식별할 정보와 확인일을 기존 기록에 남긴다.
- 양식에서 읽은 변수명·설명은 해당 원문 셀을 가리킨다. 선택칸·연도는 자료정리에서는 참고 위치만 기록하고 실제 신청 업무에서만 상태를 대조한다. 병합칸이면 좌상단 주소와 적용 범위를 기록한다. 열 문자·병합 구조는 판본별로 다시 확인한다.
- 명세가 적용 연도를 밝히지 않으면 미확인으로 둔다. 한 양식의 신청 가능연도 안내를 모든 변수의 제공연도로 확장하지 않는다. 실제 신청 업무에서는 연구 필요연도와 요청연도가 어긋나는지 확인한다.
- 서로 다른 파일에 같은 변수명이 있어도 설명·값 코드·단위·기간을 대조한다. 다른 이름을 자동 동의어로 바꾸거나 반복 행을 임의로 삭제하지 않는다.
- CSV는 시트·셀 대신 열 이름과 코드값/행 위치, PDF는 쪽·표, 승인 문서는 절·쪽을 남긴다. 근거가 가진 위치 체계를 사용한다.
- 일자 변수는 원문·현재 지침에서 확인한 단위와 형식을 기록한다. 문서의 DB 자료형을 실제 SAS 타입·길이로 간주하지 않는다.

## 코드 목록·조작적 정의·코드 작성으로 넘기기

코드 목록은 위 표의 항목 ID에 코드체계·판본, 포함/제외 코드와 하위범위, 적용기간, 근거 위치를 연결한다. 조작적 정의는 같은 항목 ID를 이용해 코드와 변수, 진단 위치/횟수, 관찰창·기준일, AND/OR 결합, 결측·제외 규칙과 현재 연구의 채택 근거를 연결한다. 정의 후보/확정 상태와 신청·제공 상태는 별도로 기록한다. 필요한 정의가 미정이면 해당 결정만 남겨두고 다른 항목의 명세 확인을 계속한다.

실행 코드는 [코드 작성 지침](code-generation_20261111.md)에 따라 원주 추출과 제공 SAS 가공을 구분한다. 원자료 도착 전의 표 검토는 문서 정합성 확인이다. 실제 스키마·키/결측/중복·연결률·연구 결과 검증을 수행한 것으로 표현하지 않는다.
