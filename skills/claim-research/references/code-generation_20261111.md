# NHIS/HIRA 코드 작성 지침

이 문서는 프로젝트의 별도 코드 작성 허브가 없는 환경에서도 사용할 수 있는 공통 기준이다. 현재 사용자 결정, 프로젝트 AGENTS.md·CLAUDE.md, 승인된 연구계획/SAP와 실제 입력 스키마가 우선한다. 연구별 상수·서버 설정·원자료·분석 결과는 포함하지 않는다.

## 1. 자료원과 단계를 먼저 구분한다

| 선택한 환경 | 먼저 확인할 근거 | 작성 방향 |
|---|---|---|
| HIRA 청구자료 | 실제 제공 프로필·테이블·개인키/명세서키·날짜 저장형 | [HIRA 의미](hira-semantic-layer.md)와 [근거](hira-evidence.md)를 적용한다. 맞춤형 자료와 표본자료의 열을 혼용하지 않는다. |
| NHIS 원주 SAS–Tibero 추출 | 승인된 접속 환경·현재 DB 명세·신청 범위·저장 권한·용량 | SAS에서 DB에 전달하는 SQL과 SAS 내부 SQL을 구분한다. 추출·저장·검수의 공용 구조와 연구별 조건을 나눈다. |
| NHIS 제공 SAS 테이블 가공 | 실제 SAS 라이브러리·테이블·키·변수형·날짜·자료 제공 단계 | 필요한 행·열을 목적별 작은 표로 추출하고 즉시 QC한 뒤 연결한다. SAS 파일 제공과 상세자료 반출 허가는 별개다. |

NHIS는 [의미와 단계](nhis-semantic-layer.md), [근거와 적용 범위](nhis-evidence.md)를 읽는다. 위치 명칭이나 파일 확장자만으로 스키마를 정하지 않는다. 원주 DB 접속·USRTMP·HBMT 계열 가정을 제공 SAS 환경으로 옮기거나 HIRA와 NHIS 변수명을 일괄 치환하지 않는다.

변수나 입력을 사용자에게 묻기 전에 현재 연구의 생성 코드, 상위 입력, 데이터 사전, PROC CONTENTS 또는 동등한 명세를 확인한다. 이미 확정된 사실을 반복해서 묻지 않는다. 근거가 없으면 구체적인 누락을 기록하고 그 정보에 의존하지 않는 작업을 계속한다.

## 2. 기존 추출표를 먼저 재사용한다

새 추출 전에 `필요 항목 → 기존 표 → 행 단위·키·날짜·코드·기간·대상 범위 → 재사용/변환/부족분 보완/미확인`을 기존 연구 기록에 대조한다. 이름·자료형만 다르면 검증된 변환을 우선한다. 생성 코드를 못 찾았다는 이유만으로 자료가 없다고 판단하지 않는다.

- 선정·제외·기저·과거력·추적·결과와 QC에 필요한 조건의 합집합을 확인한다. 최종 선정자나 노출군만 먼저 남겨 대조군 후보와 선정 근거를 잃지 않는다.
- 전체 원천을 읽어야 하는 경우와 모든 원천행을 저장해야 하는 경우를 구분한다. 전체 진단행을 전기간 누적한 뒤 나중에 줄이는 구조를 기본으로 만들지 않는다.
- 원천 보완은 필요한 사람·기간·코드·열에 맞춘다. 필터 전 전체 범위 QC가 필요한 경우에는 필요한 분모·날짜 범위·결측 요약을 함께 보존한다.
- 행 수·행 길이·월 수·큰 물리 사본·전체 정렬·디스크 여유를 기존 메타자료와 로그로 평가한다. 용량 확인 때문에 거대 원천을 다시 COUNT/DISTINCT하지 않는다. 관측값·가정·미측정을 구분한다.

## 3. 제공 SAS 테이블: 목적별 SQL 블록과 즉시 QC

기본 순서는 `기존 산출물 확인 → 목적별 작은 표 추출 → 즉시 QC → 작은 표 연결 → 코호트·분석표 → 요청된 산출물`이다. 이 순서가 고정 파일 수를 요구하는 것은 아니다.

1. 블록 위에 목적, 실제 입력, 남길 조건, 연결 키/관계, 출력과 한 행의 의미, 후속 사용처, QC·재실행 범위를 짧게 적는다.
2. 원자료 선택은 조건이 직접 보이는 `PROC SQL; CREATE TABLE ... AS SELECT ... FROM ... WHERE ...; QUIT;`를 우선한다. 필요한 열을 명시한다. 의미 없는 변환·동적 이름·중첩 래퍼로 조건을 숨기지 않는다.
3. 반복되는 월·연도 처리와 실제 재사용되는 작은 검사는 매크로로 둘 수 있다. 서로 다른 준비·추출·판정·분석 전체를 큰 실행 매크로에 넣지 않는다. 필요한 DATA step, BY/RETAIN, 정렬, 통계 PROC를 SQL로 억지로 바꾸지 않는다.
4. T40의 개인키 존재를 가정하지 않는다. 현재 자료에 확인된 명세서키로 T20에 연결하고 키의 유일성·범위를 검증한다. 같은 개인이라는 이유로 서로 다른 청구를 연결하지 않는다. 상세행끼리의 N:M 증식을 DISTINCT로 숨기지 않는다.
5. 파일 월과 진료·처방·index 날짜를 구분한다. 월 이월이나 경계일이 있으면 필요한 기간의 키와 승인된 날짜 의미로 연결한다.
6. SET/APPEND/UNION ALL과 중복 제거를 구분한다. 새 코드에 APPEND FORCE를 사용하지 않는다. DISTINCT/NODUPKEY는 정해진 분석 단위에서 보존할 행과 제거 근거가 있을 때만 사용하고 전후를 검증한다.
7. 표를 만들자마자 행 수·고유키·결측·날짜 범위·코드 분포·중복/상충을 확인한다. JOIN 뒤에는 매칭/미매칭·orphan·행 증식·주요 금액/일수/사건 수의 손실·중복을 확인한다. 같은 행 수만으로 동일하다고 판단하지 않는다.

[WORK SQL/QC 모의 예제](../assets/sas_templates/30_NHIS_proc_sql_block_qc_template.txt)는 합성 자료로 블록 구조를 보여준다. 실제 스키마나 연구 기준, 운영 추출 완성본, 서버 실행 검증을 제공하지 않는다. 내부 라이브러리에 옛 00·10·20 추출 예제가 있더라도 기간·상병·대상자 제한·삭제/PURGE·반출·전체 단계 래퍼를 그대로 채택하지 않는다. 이 배포본에는 그 옛 운영 예제와 연구별 실행 코드를 포함하지 않는다.

## 4. 원주 SAS–Tibero 추출

원주의 접속·SQL pass-through·월별/연도별 추출·저장 구조는 여러 연구에서 재사용할 수 있다. 그 구조를 사용한 특정 연구의 조건·기간까지 공통 기준이 되는 것은 아니다.

- 승인된 접속 설정은 현재 보안 환경에서 읽는다. 암호·계정·DSN·접속문을 배포 코드나 대화·공개 기록에 저장하지 않는다.
- 실제 DB 테이블·열·날짜·키·파티션·저장 위치와 허용량을 확인하고 DB에 전달되는 SQL을 직접 검토한다. SAS 문법과 Tibero 문법을 같은 방식으로 해석하지 않는다.
- 신청·연구 정의를 보존하는 범위에서 월별 또는 연도별 작은 작업으로 나눈다. 접속 설정, 추출, 저장, 검수, 공간 진단을 구분한다.
- 기존 표와 완료 범위를 확인한 뒤 필요한 구간만 보완한다. 대상자/제외자 생성에 쓰이는 DROP·DELETE, 정리/PURGE는 독립적인 데이터 변경 작업이며 일반 추출의 기본 선행 단계로 넣지 않는다.
- DB 부하와 저장 공간을 고려해 필요한 검수 결과를 재사용한다. 실제 서버 실행 없이 문법·권한·성능·추출 완료를 주장하지 않는다.

## 5. 중간 수정과 재실행

- 최상위의 완결된 DATA/PROC 블록 단위로 고치고 다시 실행할 수 있게 한다. 새 세션에서도 명시된 설정·작은 공통 정의와 완료된 영구 입력으로 시작할 수 있어야 한다.
- 이전 세션의 WORK·우연히 남은 매크로·지역변수에 의존하지 않는다. 필요한 재실행 중간표는 보존하되 모든 임시표를 영구 저장하는 것으로 해결하지 않는다.
- 출력 전체 재구축과 실패 월/연도 교체를 구분한다. 이미 누적된 표 뒤에 같은 자료를 다시 APPEND하지 않는다. 기존 유효 산출물은 새 결과의 필요한 QC가 끝날 때까지 보존한다.
- 입력·정의가 바뀌면 영향받는 후속 결과를 다시 계산한다. 오류 상태를 중간에 초기화하거나 빈 표의 존재만으로 성공 처리하지 않는다. 정상 0건·미처리·사건 부족·모형 추정 불가·관측 불가를 구분한다.
- 재개를 위해 큰 구간을 주석 처리하거나 GOTO·복잡한 단계 제어기를 추가하도록 요구하는 구조를 기본으로 만들지 않는다.

## 6. R 작성 방식과 분석 의미

기존 연구의 승인된 입출력·모형·공변량·가중치·시드와 패키지 조건을 먼저 읽는다. 이 사용자의 기본 작성 방식은 data.table 중심이며, 단순 분류는 조건별 `DT[조건, 변수 := 값]`으로 보이게 쓴다. `%>%`, fcase/fifelse, 일회성 함수·반복문으로 간단한 조건을 감추지 않는다. 기존 함수를 단지 짧게 만들기 위해 삭제하지 않는다.

다음은 임상 정의가 없는 합성 문법 예제다.

```r
library(data.table)
DT <- data.table(value = c(NA_real_, -1, 0, 1))
DT[, value_class := NA_character_]
DT[is.na(value), value_class := "missing"]
DT[!is.na(value) & value < 0, value_class := "negative"]
DT[!is.na(value) & value == 0, value_class := "zero"]
DT[!is.na(value) & value > 0, value_class := "positive"]
stopifnot(!anyNA(DT$value_class))
```

실제 join의 관계·키 중복·NA 처리, 그룹화·정렬·분모를 검증한다. baseline/Table 1, 매칭, KM/Cox, 하위집단·다중검정의 조건은 현재 SAP로 정한다. 다른 연구 예제의 임계값·매칭 비율·질환군·모형을 기본값으로 가져오지 않는다. 상대 입출력은 실행 작업 폴더 기준일 수 있으므로 source 파일의 보관 위치와 실제 작업 폴더를 구분한다.

## 7. 전달 전 검사와 검증 수준

현재 프로젝트의 정적 검사기와 해당 연구의 검사를 우선한다. 별도 검사기가 없으면 번들 [validate_sas_preflight.py](../scripts/validate_sas_preflight.py)를 사용한다. Python 표준 라이브러리만 필요하며 SAS를 실행하거나 원자료를 읽지 않는다. 아래 경로는 설치된 claim-research 폴더를 기준으로 한다.

```text
python -B -X utf8 scripts/validate_sas_preflight.py <전달파일1.txt> <전달파일2.txt> --json
python -B -X utf8 scripts/validate_sas_preflight.py <실행본.txt> --pair <실행본.txt> <주석본.txt> --json
python -B -X utf8 scripts/validate_sas_preflight.py --manifest <기존검수_manifest.json> --json
```

정확한 옵션은 `--help`로 확인한다. 같은 판본의 공통 정의·호출부·모든 전달 파일을 함께 검사한다. 종료 0은 구현된 정적 규칙에서 발견 없음, 1은 ERROR, 2는 REVIEW 후보가 있음을 뜻한다. ERROR는 해결하고 REVIEW는 적용 여부와 근거를 남긴다. 기준 manifest를 무조건 새로 만들거나 경고를 숨겨 통과시키지 않는다.

검사기는 완전한 SAS/매크로/Tibero 파서가 아니다. 정적 검사, 합성·예제 자료 시험, SAS/R 실행, 실자료 QC, 분석계획에 대한 타당성, 성능 측정을 구분한다. 특히 원주 pass-through SQL과 현재 서버 기능은 별도 확인한다. 실행 환경이나 데이터가 없으면 수행하지 못한 항목을 미검증으로 적는다.

기존 코드를 수정하면 필요한 범위에서 변경 전후 단계별 행 수·고유 대상자·중복·결측·매칭률·주요 분포·사건 수·주요 결과를 비교한다. 결과 동등성과 연구계획에 대한 타당성은 별개다. 승인된 정의 변경이나 오류 수정으로 결과가 달라지면 원인·영향·검증을 설명한다. 오류 재발 방지 근거는 기존 연구로그와 이슈 기록에 남기고 다음 전달 때 누적 수정 사항을 재검증한다.

## 8. 산출물과 파일 보존

표 생성만 요청받았다면 필요한 영구 테이블을 만들고 끝낸다. CSV·보고서·새 출력 폴더·별도 manifest/RUN_ID 관리 체계를 기본으로 추가하지 않는다. 이미 승인된 검증·반출 계약과 필요한 로그·QC는 보존한다. 보고서나 결과물 배포를 검토하는 경우에는 [공통 출력 QC](common-code-qc.md)를 별도로 적용한다.

새로 정하는 날짜 파일명은 `내용_YYYYMMDD.ext`로 짧게 작성하며 시·분·초를 넣지 않는다. 실행 시각은 로그/메타데이터에 기록한다. 같은 이름의 다른 내용을 임의로 덮어쓰지 않고 기존 파일명·고정 지침/설정 이름을 일괄 변경하지 않는다. ZIP은 사용자가 명시적으로 요청한 경우에만 만들며, 변경 전 보존본은 일반 파일 복사와 해시 확인으로 남긴다. 현재 프로젝트의 Git 제한과 데이터 반출 규칙을 따른다.

이 번들은 연구별 SAP·스키마·임상 코드셋·서버 접속 정보·실행 환경을 제공하지 않는다. 관리 학습 엔진은 별도 선택 기능이며, 없어도 위 작성·정적 검사 절차를 사용할 수 있다.
